# 黑话编译器：词典扩充的现状与后续计划

更新于 2026-10-02（转到 Mac 继续：命令行工具已完成，agy 的 10 批语料已用它检查过）。项目整体说明见根目录 `CLAUDE.md`，这里只记黑话词典这条线。

## 总体思路

**不让 AI 凭空编词，先从真实文本里找出编译器认不出的词，再交给 AI 填。**

两类黑话的难点不同：

| | 公文腔 | 大厂黑话 |
|---|---|---|
| 典型 | 统筹谋划、狠抓落实、坚持 X 不动摇 | 赋能、抓手、闭环、颗粒度 |
| 难点 | 四字格连成串、固定句式、压缩成缩略语的说法 | 换个名字说普通的事 |
| 靠什么解决 | 套话模板、缩略语、排比合并 | 词典 |

分工：
- **Claude**：编译框架（一次性的框架活）。
- **agy**：上网收集真实语料，按待办词表批量填词条和模板。
- **用户**：判断译文对不对（只要看大白话是不是人话、意思有没有丢，不用会说黑话）。

## 已完成（0.2.1、0.2.2，已部署到 Pages）

1. **语料 → 待办词表**（`crates/bsc-jargon/src/corpus.rs`）
   - 把整篇文章粘到黑话编译器页左边的输入框，"扩充词典"页会列出编译器不认识的词，按出现次数排序，每个词附原文例句，鼠标悬停时高亮原文。
   - 长的未收录片段（攻坚克难踔厉奋发）先统计整篇里两字、四字窗口出现的次数，再做最优切分。同样好的切法里选按四字对齐的，所以不会出现"克难踔厉"这种跨词碎片。
   - 一半已收录、一半没收录的四字格（"统筹谋划"里的"统筹"已经收录）标成"拼合"，出现两次以上才列出。
   - 给 AI 的提示词附带例句，要求它看例句判断是不是空话，拿不准的写"内容"，映射优先写上位词。
2. **参考译文集**（`crates/bsc-jargon/reference/reference.txt`）
   - 原文 + 人写的大白话。界面上和编译器的译文对照；加了一批词以后，译文变了的条目会标出来。
   - 每条原文也会跑不变式测试（还原原文、无残留黑话、内容词不丢、幂等）。
   - **现在只有 2 条，是 agy 写的草稿，还没有人审过。**
3. **缩略语**（类别"缩略"）：放管服、三农、六稳等，映射写展开后的完整说法，编译时展开，不删。核心词典里有 11 条。
4. **套话模板**（类别"模板"）：`坚持{X}不动摇 | 模板 | 一直坚持{X}`。
   - 加载时变成句式文法规则 `套话 -> 「坚持」 槽 「不动摇」`，套话块代价 4，比普通块（10）便宜，认得出就优先用模板。
   - 加权 Earley 每个位置可以有多个候选终结符（词的类别，加上模板的字面部分）。
   - 校验：E3014 槽位格式不对；E3015 映射里的槽位和模板对不上；E3016 模板字面部分有没收录的单字。
   - 核心词典里有 10 条模板。示例讲话"套话与缩略"可以演示。
5. **流程约定**
   - CI（`ci.yml`）改成只能手动运行，用户不想每次推送都跑、失败了发邮件。
   - 攒够一波功能再改修订号部署。

## 现在怎么让 agy 干活（命令行版，推荐）

agy 不用操作网页，直接读写文本文件，跑命令看结果，自己改到通过为止：

```sh
# 0. 编译一次（Mac 上）；之后直接用 target/release/bsc-jargon
cargo build --release -p bsc-jargon

# 1. 待办词表：文章里编译器不认识的词（次数、例句），后面附给 AI 填词条的提示词
target/release/bsc-jargon todo corpus/文章.txt

# 2. 按提示词写一批词条，存成纯词条文件（只有 `词 | 类别 | 映射 | 备注` 行和 # 注释）
# 3. 检查：词典校验、回归对比、参考译文对照、不变式、文章里还剩多少不认识的词
target/release/bsc-jargon check 批次.txt corpus/文章.txt
#    退出码 1 = 有错误（E 开头的诊断，或者违反不变式），回到第 2 步改；
#    警告 W3008（映射里还有黑话）也要改掉，否则会出现残留黑话、编译不幂等

# 4. 看某篇文章最终的译文和每处改动的理由
target/release/bsc-jargon run corpus/文章.txt -l 批次.txt
```

通过后交给用户看第 2、3 部分（译文变化和参考译文对照），用户认可了再存成 `lexicon/ai-NNN.txt`、加进 `lexicon::builtin_layers()`。

## agy 第一轮语料（corpus-batch-001 ~ 010）的检查结果（2026-10-02）

agy 在 Steam Deck 上交了 10 个文件，每个文件里是：来源说明 + 原文段落 + 分析过程 + 约 100 条候选词条 + 参考译文。
用命令行工具检查（10 批词条合在一起，配上各批的原文段落）：

- **词条格式和校验**：1071 行词条，3 个错误（E3016：模板「对{X}……」的单字「对」），93 个警告（W3008：映射里还有黑话，
  比如「压茬推进 → 接连不断推进」里的「推进」「不断」，「齐头并进 → 一起推进」），35 个提示（N3011 映射过长）。
- **不变式**：63 段输入里有 26 段不满足——几乎都是上面的 W3008 造成的残留黑话和不幂等。
  也就是说：**这批词条现在不能直接收进词典**，要让 agy 用 `check` 把 W3008 和 E3016 改干净。
- **候选词和语料对不上**：只有 469 / 1071 条候选词真的出现在它附的原文段落里，其余是 agy 自己联想的。
  联想的词不一定错，但违背了"先从真实文本里找出编译器认不出的词"的原则，回归对比也测不到它们。
- **来源可疑**：抽查的网址里，gov.cn 的两个（content_6929941、content_6926362）是 404，
  文旅那一批引用的标题（"……大唐不夜城经验复盘"）搜不到；文件本身（国发〔2024〕3号等）是真的，但摘的原文可能被改写、拼接过。
  大厂那几批（002、007、008、009、010）引用的媒体文章大多查不到。所以**这些"原文"不能当真实语料用，也不要进参考译文集**。
- 另外：大厂类文章按约定只在本地分析、不提交；这 10 个文件也不是词典格式，放在 `lexicon/` 下容易被误当成词典层。

检查时顺带发现并修好了两个编译器的问题：
1. 「以 X 为抓手进行全网营销」：句式改写「从 X 入手」把抓手后面并进同一个名词组的内容（"进行全网"）吞掉了。
   现在触发词后面的内容原样接在后面（「从 X 入手进行全网营销」）；触发词前面有实际内容时不做这个改写。
2. 「提高效益」被切成「提｜高效｜益」，删掉修饰语「高效」后变成「提益」。两种切法代价相同，原来随便取一个；
   现在代价相同时选黑话词占字少的切法（宁可漏认，也不切碎普通词）。

还没处理的：「以改革为引擎推进工作」→「靠改革推动推动工作」（句式改写和后面的动词重复，公共子表达式消除没跨块合并）。

## 网页手动版（不方便用命令行时）

1. 把下面的"收集语料"提示词发给 agy，让它从网上摘真实原文。
2. 把原文粘进网页，到"扩充词典"页复制提示词，交给 agy 填词条。
3. 把 agy 的输出粘回批次框，看三样：校验错误、回归对比、参考译文对照。
4. 满意的话，把词条和参考译文发给 Claude，由 Claude 存成 `lexicon/ai-NNN.txt`、加进 `lexicon::builtin_layers()`，参考译文并进 `reference.txt`。

收集语料的提示词：

```
帮我收集"官话、套话、互联网黑话"的真实语料，用来测试一个把黑话翻译成大白话的程序。

要求：
1. 只摘真实存在的公开文本，不要自己编写或改写。每段注明来源（标题 + 网址）。
2. 这一批只收【公文】（或：【互联网大厂】）一类。
3. 摘 5–8 段，每段 300–800 字，挑套话密集的段落（四字格成串、"坚持……不动摇""以……为抓手"之类）。
4. 来源尽量分散：不同地区、不同年份、不同部门（或不同公司），不要都摘同一篇。
5. 每段之后，再挑其中 2 句，写出你理解的大白话意思（只说实际要做什么，空话删掉）。

输出格式：
## 来源标题（网址）
原文：……
参考：第 1 句原文 → 大白话；第 2 句原文 → 大白话
```

语料版权：官方文件不受著作权保护（著作权法第五条），可以挑几段进仓库当参考译文；大厂文章只在本地分析，不提交。

## 后续计划（按顺序）

1. ~~**命令行工具 `bsc-jargon`**~~（已完成，见上面"命令行版"）
   - 为什么要做：网页是 egui 画在画布上的，agy 没法可靠地操作它，读不出校验结果。
   - 三个子命令，读写普通文本文件，调用和网页同一套编译器代码：
     - `todo 文章.txt`：输出待办词表和带例句的提示词；
     - `check 批次.txt [文章…]`：校验诊断、回归对比、参考译文对照；
     - `run 文章.txt`：译文，加上每处改动的理由。
   - agy 的循环：找语料 → todo → 填词条 → check → 有错误就自己改 → 交给用户看对比结果。
   - 在 Mac 上编译（几秒钟），Steam Deck 上不编译。
2. **网页"扩充词典"页加上收集语料的提示词**：和填词条的提示词放在一起，不用每次从文档里翻。
3. **扩充词典**：agy 按领域分批（ai-002、ai-003……，每批约 100 条，一批只收一类），参考译文跟着增加到 30–50 条。
4. **检查缩略语展开后的译文是否通顺**：测试只检查了关键片段在不在。展开后放在句子里可能显得别扭（"深化简化审批、加强监管、改进服务改革"），需要人看一遍，可能要调整生成方式（比如加"的"或改成"X（即……）"，后者要注意不破坏幂等）。
5. **自动发现套话句式**：待办词表只能找出不认识的词，"坚持 X 不动摇"这类句式找不出来。可以统计"字面部分相同、中间内容不同"的重复片段，产出模板候选。
6. **按领域分文件**：文件头写 `#! 领域: 公文` / `大厂`，界面上可以按领域开关，水分也能分开统计。等真遇到同一个词在两个领域意思不同时再做。
7. **反向编译**（大白话 → 黑话）：复用同一个 IR，换一个后端。

## 注意事项

- 词典新类别的写法和校验规则在 `lexicon/core.txt` 开头的注释里，`ai_prompt()` 里也有给 AI 的说明。
- 模板的字面部分如果没收录，会自动登记成"内容"词（层号是模板所在的层），所以"这一批收录 N 条"会把它们也算进去。
- 本机是 Steam Deck 时不要编译（资源不够）；Mac 上可以本地编译、测试。
